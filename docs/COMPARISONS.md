# Comparing Agile V with Other Approaches

Agile V is an evidence-oriented lifecycle for work that benefits from baselined requirements, typed traceability, role separation, risk-scaled controls, human gates, and explicit verification. The alternatives below solve overlapping but not identical problems; they can be combined.

| Approach | Strong fit | Add Agile V when | Useful combination |
|---|---|---|---|
| Raw prompting | Exploration, ideation, one-off transformations, and low-consequence tasks where durable lifecycle records are unnecessary | The output enters a production, security, regulated, safety, or externally reviewed path | Use prompting inside a bounded Agile V stage; persist accepted intent and evidence rather than treating chat as the source of truth |
| Spec-driven development | Teams want explicit specifications, acceptance criteria, and implementation aligned to a spec | Independent findings, frozen baselines, typed requirement/artifact/test links, risk records, gates, or release evidence are also needed | Keep the existing spec format; map approved revisions to `REQ-XXXX`, baseline references, tests, and verification records |
| Conventional V-model | Programs already organize decomposition on the left and integration/verification on the right | Agent context boundaries, AI influence provenance, iterative change records, or machine-readable evidence controls need to be made explicit | Retain organizational V-model procedures and use Agile V skills/templates as an agent-operating and evidence layer |
| Adjacent agent workflow frameworks | Tool orchestration, planning, memory, multi-agent delegation, coding loops, or runtime execution are the primary need | The workflow requires risk classification, human approval evidence, independent verification, lifecycle traceability, or AI-run provenance | Let the framework execute tasks while Agile V constrains stage inputs, role separation, evidence outputs, and stop conditions |

## Selection Guide

Use the lightest approach that satisfies the task:

- Prefer raw prompting for isolated `L0` exploration with no production credentials or regulated path.
- Prefer a spec-driven workflow when specification quality is the central need and existing review/evidence controls are sufficient.
- Prefer an organizational V-model where it is already mandated; do not replace controlled procedures merely to adopt agent tooling.
- Prefer an adjacent agent framework for runtime capabilities such as orchestration or tool execution.
- Add Agile V when consequences justify durable baselines, trace links, independent challenge, human gates, risk-scaled evidence, or controlled evolution.

Combination does not make a workflow compliant or safe by itself. Map responsibilities and authoritative records, test the integration, preserve framework provenance, and obtain decisions from the accountable human roles. For practical entry points, see [Tutorials](tutorials/README.md).
