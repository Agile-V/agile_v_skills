# k8s-aibom Integration

## Overview

[k8s-aibom](https://github.com/GoogleCloudPlatform/k8s-aibom) is a Kubernetes controller from GoogleCloudPlatform that generates CycloneDX 1.6 ML-BOM documents for AI workloads at runtime.

Agile-V can import k8s-aibom artifacts to satisfy the `observed` side of the AI_RUN_MANIFEST for Kubernetes-hosted AI inference and agent stacks.

## What k8s-aibom Inventories

- Inference serving runtimes: vLLM, Hugging Face TGI, NVIDIA Triton, Ollama, Ray Serve, SGLang, LMDeploy
- Agent frameworks: LangChain, LangGraph, AutoGen, CrewAI, Langflow, Flowise, Chainlit
- Vector/RAG infrastructure: Milvus, Qdrant, Weaviate, Chroma, pgvector
- Training and evaluation workloads

## Integration Modes

### Mode A: Manual Import

User provides a CycloneDX ML-BOM generated by k8s-aibom.

```yaml
# In AI_RUN_MANIFEST.yaml
runtime_inventory:
  source: "k8s-aibom"
  imported_bom: ".agile-v/aibom/AAV-0000/k8s_runtime.cdx.json"
  imported_bom_hash: "sha256:"
  confidence: "verified"
```

### Mode B: CI Import

CI fetches the latest runtime BOM artifact and attaches it to Agile-V evidence.

```yaml
# In CI pipeline (pseudocode)
steps:
  - name: Fetch k8s-aibom
    run: |
      kubectl get mlbom -n ai-workloads -o json > .agile-v/aibom/${TASK_ID}/k8s_runtime.cdx.json
      sha256sum .agile-v/aibom/${TASK_ID}/k8s_runtime.cdx.json
```

### Mode C: Kubernetes Runtime Observation

Runtime controller emits BOMs for AI workloads; Agile-V references those BOMs in release evidence.

## Fields to Import from k8s-aibom

When a k8s-aibom document is available, import or link:

| k8s-aibom Field | AI_RUN_MANIFEST Target |
|----------------|----------------------|
| container image + digest | `agent_runtime.sandbox_image`, `sandbox_image_digest` |
| inference runtime identity | `models[].inference_runtime`, `runtime_version` |
| model identity | `models[].name`, `model_id` |
| agent framework | `agent_runtime.agent_framework`, `framework_version` |
| external LLM API dependencies | `external_services[]` |
| RAG/vector infrastructure | `rag_and_context.vector_store` |
| confidence values | all `confidence` fields |
| BOM generation timestamp | `identity.created_at` |
| source workload identity | `agent_runtime.orchestrator` |

## Validation Rules

### L2+ Tasks

If the agent run or deployed system used a Kubernetes AI runtime and a k8s-aibom artifact is available, the Agile-V evidence bundle MUST either:

1. Link the k8s-aibom artifact, OR
2. Explain why runtime inventory was unavailable.

### L3/L4 Tasks

Missing runtime inventory is a verifier finding unless explicitly risk-accepted by a human approver.

## Example: Importing a k8s-aibom Artifact

```yaml
# AI_RUN_MANIFEST.yaml excerpt
agent_runtime:
  agent_name: "vLLM inference server"
  agent_framework: "vLLM"
  framework_version: "0.4.2"
  execution_environment: "kubernetes"
  sandbox_image: "vllm/vllm-openai:v0.4.2"
  sandbox_image_digest: "sha256:abc123..."
  orchestrator: "Kubernetes/inference-namespace"
  confidence: "verified"
  evidence_locator: "k8s-aibom: .agile-v/aibom/AAV-0000/k8s_runtime.cdx.json"

runtime_inventory:
  source: "k8s-aibom"
  imported_bom: ".agile-v/aibom/AAV-0000/k8s_runtime.cdx.json"
  imported_bom_hash: "sha256:bcd234..."
  confidence: "verified"
```
